# Bestehende Archive für Pfennig 0.10.0

Die Chatfunktion braucht eine neue Tabelle `gespraeche`. Außerdem gehört eine Zeile in `anfragen` jetzt entweder zu einer Datei oder zu einem Gespräch: `datei_id` darf leer sein, `gespraech_id` ist neu. Ein 0.9.0-Archiv hat beides nicht, und die App ändert kein bestehendes Schema.

Die unten beschriebene einmalige, manuelle Korrektur erhält alle Buchungen, Dateien, Einstellungen, Aktivitäten und die Importhistorie. Nur die Tabelle `anfragen` bekommt ihre neue Form, mit denselben Zeilen, IDs und dem bisherigen höchsten Zähler. Ältere `konversation`-Werte behalten ihr bisheriges Format; nichts liest sie.

Das SQL-Arbeitsblatt ist kein Bestandteil der App und wird nie automatisch ausgeführt. Es ist ausschließlich für das ausgelieferte 0.9.0-Schema gedacht. Es prüft die erwarteten Spalten, Zeilenzahl und Datenbankintegrität und führt die Änderung transaktional aus. Ein zweiter Lauf wird abgewiesen. Nicht auf andere Schemas anpassen oder bei einem Fehler fortfahren, ohne dessen Ursache zu prüfen.

## Je Rechner separat

1. Pfennig vollständig beenden, einschließlich laufender Importe.
2. Datenbank und Originaldateien sichern.
3. Das [SQL-Arbeitsblatt für 0.10.0](0.10.0.sql) auf die lokale 0.9.0-Datenbank anwenden.
4. Erst nach erfolgreicher Prüfung die aktualisierte App öffnen.

## Befehle für das Releasearchiv

Nach dem Beenden der App ausführen. Den Pfad in `pfennig_sql` an den tatsächlichen Ort des Arbeitsblatts anpassen. Für das Entwicklungsarchiv `Pfennig` durch `Pfennig-Dev` ersetzen.

```sh
pfennig_archive="$HOME/Library/Application Support/Pfennig"
pfennig_backup="$pfennig_archive/Backups/vor-0.10.0-$(date +%Y%m%d-%H%M%S)"
pfennig_sql="$HOME/Downloads/0.10.0.sql"

(
  set -eu
  test -f "$pfennig_archive/pfennig.sqlite"
  test -f "$pfennig_sql"
  mkdir -p "$pfennig_backup"
  sqlite3 -readonly "$pfennig_archive/pfennig.sqlite" ".backup '$pfennig_backup/pfennig.sqlite'"
  for pfennig_folder in Archiv Inbox; do
    if [ -d "$pfennig_archive/$pfennig_folder" ]; then
      ditto "$pfennig_archive/$pfennig_folder" "$pfennig_backup/$pfennig_folder"
    fi
  done
  sqlite3 -bail "$pfennig_archive/pfennig.sqlite" < "$pfennig_sql"
)
```

Erwartete Ausgabe: `ok`. Bei einem Fehler die neue App noch nicht mit diesem Archiv starten; die Sicherung bleibt unberührt. Ein bereits mit 0.10.0 angelegtes Archiv benötigt keine Korrektur.

Geprüft an einer synthetischen 0.9.0-Datenbank: `sqlite_master` stimmt danach exakt mit einem frisch angelegten Archiv überein, der Zähler von `anfragen` bleibt erhalten, `integrity_check` ist `ok`, ein zweiter Lauf wird abgewiesen.
